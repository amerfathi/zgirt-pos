## Changes

- Refined the existing Web, Windows and Android interface without changing business posting or sync rules: consistent indigo/white/dark surfaces, clearer navigation, legible controls and a reachable sale total on mobile.
- Simplified public Web landing text and aligned its color with the app. The public trial and branch-upgrade WhatsApp links now contact the platform owner at `+966564982852`.
- Added preset Arabic currencies plus USD and EUR in settings; custom entry and existing currency settings remain. This is a label choice, **not** foreign-exchange conversion or monetary data migration.
- Corrected the cloud settings pending-change display so it reads the actual queue length before showing a number.
- Removed unsupported wording from printed A4 invoices and retained the current BRAKA identity on invoices and reports.

## Verification and limitations

- Local Web and Windows/Android test fixtures checked navigation across 39 surfaces each. This is a navigation smoke test, not deep certification of every action.
- The public Web landing passed browser checks at desktop and narrow widths for runtime errors, horizontal overflow, contact URL, headline and main color.
- A test A4 invoice was submitted to the physical HP printer; the Windows print service recorded one page, but paper appearance still needs owner confirmation.
- Windows package content can be smoke-tested without installing. The owner chose not to replace the installed copy for an upgrade test. Therefore the actual 2.6.10 installer upgrade path is unverified on that computer.
- The Windows EXE remains without a trusted Authenticode signature; the signed update manifest is a separate integrity control and does not remove the Windows unknown-publisher warning.
- Automated accounting tests use UTC on the host because a pre-existing local-date test can fail around the Riyadh/UTC day boundary; this is not a blanket timezone certification.
